2026ydriver 사용설명서

STM32F103 기반 듀얼 DC 모터 드라이버 (리프트 / 방제차 / AS(아성) 공용) — 2026-09-05

1. 시스템 개요

2026ydriver는 STM32F103Rx(LQFP64) 기반의 듀얼 DC 모터 드라이버입니다. 로컬 입력(FNR 레버 + 스로틀)과 CAN 원격 명령을 모두 지원하며, 하나의 펌웨어로 리프트(삼부), 방제차(삼부), AS(아성 ESP32 인터페이스) 3종의 상위 컨트롤러와 호환됩니다.

항목내용
MCUSTM32F103RBT6 / RCT6 (LQFP64), 내부 RC(HSI) 기반 36MHz
모터 출력2채널 H-브리지 PWM (TIM2/TIM3), BEMF 기반 RPM 추정 + PID
배터리STM32_SB100D_BJ 기본24V. 상위 명령으로 정지 중24/48V 선택 가능, 자동 전압 전환 없음
CAN500 kbps, 트랜시버 SN65HVD232(3.3V)
표시1자리 FND (74HC595 구동, 에러코드/FNR 상태)
워치독IWDG 약 12.8초

5. 전원 투입 시퀀스 (DC-Link)

  1. 부팅 → 모델 선택 확인, 전체 릴레이 OFF, CAN 전용 대기 (PA8 미사용)
  2. MC2(프리차지) ON → 1초 대기 (DC-Link 커패시터 충전)
  3. MC1(메인) ON → 0.5초 대기 (스위칭 과도 안정화)
  4. DC-Link 전압 측정 → 모델 고정 24V와 측정값 로그, 24V 보호 기준 사용
  5. 션트 과전류 보호(ADC2 아날로그 워치독) 활성화
  6. SD(브리지 인에이블) High → 구동 준비 완료, FND에 0 표시

전원 차단(power_off) 시에는 SD 차단 → MC1·MC2 동시 개방 → 0.5초 후 전체 릴레이 OFF 순서입니다.

7.1.1 바이트 6 — MY_TOGGLE 비트 정의

7.2 송신: VCU 상태 (0x5B8, 100ms 주기, DLC=8)

바이트내용비고
0~2RPM1(12bit) + RPM2(12bit) 패킹-3600~+3600 → 0~4095 인코딩, 전송 배율 1.667
3전류 [A] (8bit)홀 센서(WCS1600) 측정
4~6배터리×10(10bit) + 모터온도(7bit) + FET온도(7bit) 패킹배터리 0.1V 해상도(+0.5V 보정)
7상태 플래그bisang(비상), emb, emb_error, can_ready, limitSwitch, spray
아성 ESP32 인터페이스는 이 0x5B8 프레임을 수신하여 LCD에 전압·속도·온도를 표시합니다.

DM_DRIVER에서는 삼부 LCD(ycb_samboo_auto_lcd) 호환을 위해 Byte7 bit5에 C+(PC0, 충돌), bit6에 C−(PC1, 호스) 상태를 전송합니다. LOW=활성이며 limitSwitch 값은 0=미감지, 1=C+만 감지, 2=C−만 감지, 3=동시 감지입니다. 주행 명령의 ioMsg와 무관하게 갱신하며, 상위 LCD 소스 수정 없이 기존 수신 필드를 사용합니다. 입력에 따른 정지 판단은 상위에서만 수행합니다.

7.3 설정 프로토콜 (미지원)

0x700(설정 요청) / 0x708~0x70C(저장) / 0x5B0~0x5B7(응답) 프로토콜은 수신은 되나 본 펌웨어에서는 비활성화 상태입니다(SYSTEM_CONF 미사용). 해당 프레임 수신 시 무시 로그만 출력합니다.

7.4 PCB별 입력·릴레이 상태 (0x5B9, 100ms 주기, DLC=8)

주행 CAN 연결이 활성 상태일 때 0x5B8 직후 연속 전송합니다. 기존 0x5A1을 대체하며 0x5A0은 유지합니다.

Core/Inc/system_setup.h의 PCB_TYPE 기본값은 DM_DRIVER입니다. 이 타입은 FND를 초기화하거나 사용하지 않으며, 참조 프로젝트와 동일하게 C+=PC0, C−=PC1, D+=PC2, D−=PC3를 Pull-up 입력으로 사용합니다. D−의 상승 에지 EXTI 설정은 참조 프로젝트와 동일하게 유지합니다. 기존 FND 보드는 FND_DRIVER로 선택합니다. FND_DRIVER의 RY8은 PD0이며 HSI를 사용하는 LQFP64 보드에서 PD0/PD1 리맵 후 LOW 출력으로 초기화합니다. DM_DRIVER에서는 PD0를 초기화하거나 읽지 않습니다. RY8 제어 명령은 추가하지 않습니다.

입력은 LOW=1, 출력은 실제 출력 래치 HIGH=1입니다(브레이크 체결 여부와 구분). ADC는 0~4095 범위 제한 후 4비트 우측 시프트하여 256단계로 전송합니다. 상위 LCD에서 확장 데이터를 사용하려면 0x5B9 수신 파서를 추가해야 합니다. 이 변경은 드라이버 송신만 적용합니다.

충돌 리미트를 포함한 입력은 상위로 상태만 전달하며, 드라이버 내부에서 모터 정지나 주행 차단에 사용하지 않습니다. 정지 판단은 상위에서 수행합니다. 기존 0x5A0 및 0x5B8 포맷은 변경하지 않습니다. DM_DRIVER에서는 FND 표시 대신 CAN 오류 코드와 UART 로그로 상태를 확인합니다.

8.1 RPM PI 제어의 저속 비활성 구간

모델 클래스의 PID_CONTROL_CONFIG typedef로 PID 설정을 묶어 사용합니다. PID 초기화 순서는 disable, Kp, Ki, Kd이며 기본값은 {false, 0.8f, 0.1f, 0.0f}입니다. 첫 값을 true로 변경하면 상위 CAN 명령과 관계없이 PID 보정을 사용하지 않습니다. 실제 비활성 조건은 모델 PID.disable 또는 CAN disablePID입니다. 비활성 시 PID 보정·적분을 초기화하며 가감속, 브레이크, 속도 측정 및 보호 기능은 유지합니다.

현재 속도 제어는 BEMF(역기전력)를 ADC로 측정하여 실제 RPM을 계산하고, 목표 RPM과의 오차를 PI 보정 PWM으로 변환합니다. 그러나 저속에서는 BEMF 전압이 작아 ADC 오프셋, PWM 스위칭 노이즈 및 모터 리플의 영향이 상대적으로 커지므로 RPM 측정 신뢰도가 낮습니다. 이 구간에서 PI를 사용하면 측정 노이즈를 실제 속도오차로 판단하여 급격한 PWM 보정, 헌팅, 적분 누적, 정지 부근의 미세 구동 또는 좌우 속도 불균형이 발생할 수 있습니다.

속도 조건PI 상태제어 동작설계 목적
목표 또는 실제속도 500rpm 미만해제선형/S-curve 램프 PWM만 적용하고 PI 적분값 초기화불안정한 저속 BEMF 측정값에 의한 헌팅과 급출발 방지
목표와 실제속도 모두 600rpm 이상활성화램프 PWM에 RPM 오차 기반 PI 보정값을 합산BEMF 측정이 안정된 구간에서 부하 변화와 좌우 속도 차이 보정
500~600rpm이전 상태 유지직전 PI 활성/비활성 상태를 유지경계 부근 RPM 리플로 PI가 반복 전환되는 채터링 방지

PI 진입 기준 600rpm과 해제 기준 500rpm 사이의 100rpm 차이를 히스테리시스라고 합니다. 예를 들어 측정속도가 500rpm 부근에서 반복해서 흔들리더라도 PI가 매번 켜지고 꺼지지 않도록 합니다. PI 진입 직후 또는 가속 램프 동작 중에는 보정 PWM을 ±5%로 제한하고, 안정된 정속 구간에서는 최대 ±20%까지 허용합니다. 보정 출력에도 10ms 단위 변화율 제한을 적용하여 한 번의 RPM 노이즈가 PWM 급변으로 이어지는 것을 방지합니다.

500/600rpm은 모든 모터에 공통인 절대값이 아니라 현재 모터와 BEMF 측정 회로에 맞춘 제어 기준입니다. 모터 또는 전압 사양을 변경할 경우 저속 RPM 로그와 BEMF 노이즈를 확인하여 PID_LOW_SPEED_THRESHOLD 및 PID_LOW_SPEED_EXIT_THRESHOLD를 재조정해야 합니다.
