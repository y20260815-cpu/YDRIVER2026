1. 시스템 개요

YCB 듀얼 모터 드라이버(NO CAN)는 STM32F103RBTx 마이크로컨트롤러 기반의 차량용 듀얼 DC 모터 제어 시스템입니다. 포텐셔미터(스로틀), 전후진 스위치, 좌우정지 스위치를 통한 로컬 입력으로 동작하며, CAN 버스가 연결되지 않은 단독 구동 환경에 최적화되어 있습니다.

NO CAN 버전 동작 방식
CAN 통신이 없거나 타임아웃이 발생하면(canReady = 0) 자동으로 로컬 입력(포텐셔미터·스위치)을 사용합니다. CAN이 연결된 경우 DCU 정보(RPM, 온도, 배터리 전압)를 0x588 ID로 송신합니다.

주요 특징

듀얼 모터 독립 제어

  • 모터1 / 모터2 개별 방향 및 속도 제어
  • 극성 반전 설정 (motor1/2_polarity)
  • FET 데드타임 자동 확보 (방향 전환 시)

부드러운 가감속 (LogRamp)

  • 로그 기반 비선형 가속·감속 곡선
  • accel / decel 파라미터로 응답 속도 조정
  • 오버슈팅 방지 처리

전속도 PID 부하 보상 제어

  • BEMF 기반 실제 RPM 측정
  • 스로틀 입력이 있으면 전속도 구간에서 PID 보정 적용
  • 부하 증가로 RPM 저하 시 PWM 자동 증가 (최대 +20%)
  • stop_throttle 시 적분 리셋 (Anti-windup)

다중 보호 기능

  • FET 온도 과열 보호 (10초 연속 초과 시 차단)
  • 방향 전환 시 PWM 자동 0 (딜레이 보호)
  • 독립 워치독 (IWDG)

전자 브레이크 (EMB) 제어

  • 모터 정지 시 자동 EMB 체결
  • EMB 해제 후 소프트 스타트 (200ms)
  • brake_delay 파라미터 조정 가능

리프트 / 밸브 제어

  • X축 리프트 UP/DN (SV1·SV2)
  • W축 캐스트 UP/DN (CSV1·CSV2)
  • 리밋 스위치 연동 자동 정지

5. 모터 제어 알고리즘

5.1 전체 제어 흐름

[스로틀 ADC] ──scale_value()──┐ [리밋 ADC] ──val/4096 ──────┤ [전후진SW (jenhujin)]──────────┤ [좌우정지SW (t_sw)]────────────┤ ▼ Calcu_sourcePWM(throttle, limit, jenhujin_key, t_sw) │ Calcu_limit() → control_value (0.2~1.0 구간 리매핑) │ jenhujin=0(중립) → 스핀 처리 │ jenhujin=1/2 + t_sw=1/2 → gamsok_ratio[brake_rate] 적용 ▼ Calcu_targetPWM() │ 극성(polarity) XOR로 실제 방향 판단 │ 방향별 fwd_ratio / bwd_ratio 적용 │ FET보호 or 방향전환중 → src.f1=f2=0 │ PWM_UpdateRoutine() × 2 (LogRamp) │ jenhujin_confirmed=2(후진) → ×(-1) ▼ inputRaw.target_pwm (.f1 / .f2) ▼ Update_PWM(disable_pid=0, target_pwm1, target_pwm2) │ BEMF 측정 → 현재 RPM │ target_rpm = target_pwm × MOTOR_MAX_RPM │ error_rpm = target_rpm − current_rpm_adj │ stop_throttle=0 → PID 보정 적용 (전속도) │ stop_throttle=1 → 오픈루프 + 적분 리셋 │ pid_pwm 클램프 ±0.2f → 폭주 방지 │ 데드존 적용 (|pwm| < 0.05 → 0) ▼ Dual_Motor_set_pwm10() → TIM2 / TIM3 CCR 직접 기록

5.2 LogRamp (가감속 곡선)

PWM_UpdateRoutine()은 매 10ms 루프마다 호출되어 현재 PWM 값을 목표값에 점진적으로 추종시킵니다.

// LogRampStep: 로그 기반 스텝 계산 k = (|target| < |current|) ? decel_rate : accel_rate; step = k × log(|error| + 1); // error가 클수록 큰 스텝 // 공식: accel_rate = sysConf.accel / 500.0f // decel_rate = sysConf.decel / 500.0f // 기본값: accel=10 → 0.020, decel=20 → 0.040
스로틀이 0(stop_throttle=1)이면 targetPWM을 0.0으로 강제 설정하여 감속 경로를 따라 자연스럽게 정지합니다.

5.3 전후진 비율 및 극성 처리

전진/후진 입력에 따라 각 모터에 적용되는 최대 PWM 비율이 다릅니다. 모터 극성도 XOR 연산으로 반영합니다.

// jenhujin_key: 1=전진, 2=후진 uint8_t intent_fwd = (jenhujin_key == 1) ? 1 : 0; uint8_t m1_fwd = intent_fwd ^ (motor1_polarity ? 1 : 0); uint8_t m2_fwd = intent_fwd ^ (motor2_polarity ? 1 : 0); src.f1 *= m1_fwd ? fwd_ratio : bwd_ratio; // fwd_ratio = foreward/100 src.f2 *= m2_fwd ? fwd_ratio : bwd_ratio; // bwd_ratio = backward/100

5.5 방향 전환 보호

전후진 스위치가 변경되면 JENHUJIN_SWITCH_CHANGE_FLAG=1이 설정되어 PWM 출력을 0으로 강제합니다. 양쪽 모터 PWM이 모두 0.2 미만으로 낮아진 뒤에야 새로운 방향이 반영됩니다.

5.6 BEMF 기반 RPM 측정

모터 구동 중 잠시 FET를 모두 OFF 시키고 역기전력(BEMF)을 ADC8/9로 측정합니다.

BEMF_GAIN = MOTOR_MAX_RPM / 24.0f = 87.5 RPM/V // BEMF 전압 계산 vf = (adc / 4095.0f) × 3.3V / OPAMP_GAIN // OPAMP_GAIN = 0.0567 vBEMF = vf − bemf_offset // offset: 38.35 / 38.72 (측정값) if (vBEMF > 0) vBEMF *= 2.91f // 정방향 보정 계수 rpm = vBEMF × BEMF_GAIN // 스파이크 필터: 이전 값 대비 40% 이상 급감 시 직전 값 유지
BEMF 측정 주의
FET가 OFF 되는 순간(약 2.5μs) 동안 모터 전류가 순단됩니다. BEMF 오프셋(38.35, 38.72)은 하드코딩된 값으로, 하드웨어 변경 시 재조정이 필요합니다.

5.7 전속도 PID 부하 보상 제어

5.7.1 왜 저속 제한이 문제였는가

이전 구현은 목표 RPM < 500인 경우에만 PID를 활성화했습니다. 이 방식에서는 스로틀 80% 주행 중 경사로나 적재 부하로 RPM이 500 이하로 떨어져도 PID가 고속 구간이라 판단해 보정을 하지 않는 문제가 있었습니다.

5.7.3 전속도 PID 동작 공식

// PI 계산 (PID_Compute1/2) integral += error; // Anti-windup: ±500 클램핑 pid_pwm = rpm_to_pwm_scale × (Kp × error + Ki × integral) // rpm_to_pwm_scale = 1 / 2100 ≈ 0.000476 // pid_pwm 폭주 방지 클램프 (2중 안전망) pid_pwm = clamp(pid_pwm, −0.2f, +0.2f) // 적용 조건: 스로틀 입력이 있는 모든 구간 out_pwm = (!stop_throttle) ? raw_pwm + pid_pwm : raw_pwm // stop_throttle 시 오픈루프 + 적분 리셋

CAN이 연결된 경우 100ms마다 8바이트 데이터를 송신합니다:

바이트내용인코딩

3전류 (8bit)measure_m12_current / 16
4~6배터리 전압(10bit) + 모터 온도(7bit) + FET 온도(7bit)pack7() 함수

전송용 RPM은 표시용 보정값 적용: 전진 × 1.667, 후진 × 2.174 (상부 DCU 표시 기준). 내부 제어에 사용되는 pPWM->rpm은 변경하지 않습니다.

11. CAN 설정기 연결 및 설정 시퀀스

YCB 듀얼 모터 드라이버는 CAN 버스를 통해 외부 설정기(PC 툴 등)와 연결하여 SYSTEM_CONF 파라미터를 읽고 쓸 수 있습니다. 설정기와의 통신은 요청(Request) → 응답(Response) 구조로 동작하며, 수신 완료 후 체크섬이 일치하면 Flash에 자동 저장합니다.

11.1 CAN ID 할당

설정기 → DCU (요청)0x700설정 데이터 요청 (8바이트 무관)
DCU → 설정기 (응답)0x5B0 ~ 0x5B5SYSTEM_CONF 6패킷 × 8바이트 = 48바이트
설정기 → DCU (쓰기)0x708 ~ 0x70C변경된 SYSTEM_CONF 5패킷 × 8바이트 = 40바이트

RX 필터: 0x700 ~ 0x70F 범위만 수신 (FilterMask 0x7F0). 설정기 패킷(0x708~0x70C)도 이 범위 내에 포함됩니다.

11.2 설정 읽기 시퀀스 (설정기 → DCU 요청)

// ① 설정기가 0x700 ID로 CAN 메시지 전송 (데이터 내용 무관) 설정기 → [CAN 0x700] 8바이트 // ② DCU: HAL_CAN_RxFifo0MsgPendingCallback() 에서 수신 // canFlag.needTxsetupData = 1 세트 // canFlag.needRxConfigData = 0 클리어 (진행 중인 쓰기 취소) // sysFlag.savedConfigOK = 0 클리어 // ③ main() 루프에서 needTxsetupData 감지 pCAN->canFlag.needTxsetupData = 0; pCAN->CAN_Request_Setup_Data(); // 6패킷 전송 // ④ CAN_Request_Setup_Data() 내부: // memcpy(canTX_Data, &sysConf, 48바이트) // put_canTxd(0x5B0, buf[0]) → 10ms 딜레이 // put_canTxd(0x5B1, buf[1]) → 10ms 딜레이 // ...반복 (총 0x5B0 ~ 0x5B5) DCU → [CAN 0x5B0] 8바이트 (SYSTEM_CONF [0..7]) DCU → [CAN 0x5B1] 8바이트 (SYSTEM_CONF [8..15]) DCU → [CAN 0x5B2] 8바이트 (SYSTEM_CONF [16..23]) DCU → [CAN 0x5B3] 8바이트 (SYSTEM_CONF [24..31]) DCU → [CAN 0x5B4] 8바이트 (SYSTEM_CONF [32..39]) DCU → [CAN 0x5B5] 8바이트 (SYSTEM_CONF [40..47])

11.3 설정 쓰기 시퀀스 (설정기 → DCU 저장)

// ① 설정기가 변경된 SYSTEM_CONF를 5패킷으로 분할 전송 설정기 → [CAN 0x708] 8바이트 (idx, battery_voltage, limit_current, limit_motor_temp) 설정기 → [CAN 0x709] 8바이트 (limit_fet_temp, alarm_Battery, cart_type, motor1_polarity) 설정기 → [CAN 0x70A] 8바이트 (motor2_polarity, tbd, reserved, tottle_offset) 설정기 → [CAN 0x70B] 8바이트 (stop_slip, foreward, backward, accel) 설정기 → [CAN 0x70C] 8바이트 (decel, brake_delay, brake_rate, checkSum) ← 마지막 패킷 // ② DCU: CAN_Request_SAVE() 에서 각 패킷을 canRcvBuff[memIdx] 에 저장 // memIdx = id - 0x708 (0x708→0, 0x709→1, ... 0x70C→4) // ③ 0x70C 수신 시: 체크섬 검증 // canRcvBuff[0..4] → buf[40바이트] 전체 합산 → sum & 0xFF if (sum == config.checkSum) { // 일치 → 저장 진행 sysFlag.SaveEEPROM = 1; // Flash 저장 요청 sysFlag.savedConfigOK = 1; canFlag.needRxConfigData = 1; // canSetConfig() 호출 요청 } else { // 불일치 → 재전송 필요 printf("##########[Error] Need Retry GetData"); } // ④ main() 루프에서 needRxConfigData 감지 pCAN->canFlag.needRxConfigData = 0; pCAN->canSetConfig(); // canRcvBuff → sysConf 복사 // ⑤ hnd_millisec_routine(): SaveEEPROM 플래그 감지 → Flash 저장 pFlash_mem->save_to_flash_config(sysConf); printf("###SaveEEPROM===");
체크섬 오류 시 동작
0x70C 수신 후 체크섬이 일치하지 않으면 SaveEEPROM, savedConfigOK가 세트되지 않으며 Flash 저장은 이루어지지 않습니다. 설정기는 0x700을 다시 보내 전체 시퀀스를 재시작해야 합니다.
