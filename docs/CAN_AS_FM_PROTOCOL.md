# AS/FM 공통 모터 CAN 규격

이 문서는 STM32 `2026ydriver`를 기준으로 하는 AS/FＭ 공통 인터페이스다.
ESP32-P4 FM 컨트롤러는 이 규격에 맞춰 송신한다.

## 물리 계층

- CAN 2.0A 표준 ID(11-bit)
- 500 kbit/s
- 멀티바이트 정수: Big-Endian(MSB first)
- 구동 명령 권장 송신 주기: 50 ms 이하
- STM32 수신 타임아웃: 300 ms (`CAN_ALIVE_TIMEOUT`, 100 ms 송신주기의 3배 여유)
- 정상 구동 프레임을 한 번 이상 수신한 뒤 타임아웃이 발생하면 FND와 UART 오류 필드에 `8`을 표시한다.

## CAN ID

| ID | DLC | 용도 |
|---:|---:|---|
| `0x701` | 8 | AS 구동 명령(기존 규격 호환) |
| `0x702` | 8 | FM(Follow Me) 구동 명령 |
| `0x703` | 1 | 모든 모드 공통 비상정지 |
| `0x5B8` | 8 | STM32 상태 응답(기존 규격) |

AS 하드웨어 모드에서는 `0x701`만 구동 명령으로 사용하며 `0x702`는 무시한다.
FM은 비-AS 상태에서 `0x702`로 명령한다. 기존 장비 호환을 위해 비-AS 상태의
`0x701`/`0x7C1` 처리는 유지한다. 같은 CAN 버스에서는 AS와 FM 상위 제어기 중 선택된
한 장치만 구동 프레임을 송신해야 한다. `0x703` 비상정지는 모드와 관계없이 처리한다.

## AS/FM 공통 구동 프레임

`0x701`과 `0x702`는 동일한 데이터 배치를 사용한다.

| Byte | 필드 | 형식/범위 | 설명 |
|---:|---|---|---|
| 0..1 | Left command | `int16`, -1000..1000 | -1000=-100%, 0=정지, 1000=100% |
| 2 | Accel time | `uint8`, 10..200 | 1 count=100 ms, 50=5.0 s, 200=20.0 s |
| 3 | Battery setting | `uint8` | 기존 AS 배터리 설정값; FM도 같은 의미로 전달 |
| 4..5 | Right command | `int16`, -1000..1000 | Left와 동일 |
| 6 | Toggle | `uint8` | 기존 `MY_TOGGLE` 비트 배치; 미사용 시 0 |
| 7 | Button/status | `uint8` | bit6=PID disable, bit7=emergency; 미사용 시 0 |

기존 AS ESP32 설정 메뉴의 `50/100/150/200`은 송신 전에 `/5` 처리된다. 따라서
각 설정의 실제 Byte2는 `10/20/30/40`이고 STM32 가속시간은 각각 `1/2/3/4초`이다.
STM32는 메뉴값을 다시 제어에 사용하지 않고 실제 수신 Byte2를 기준으로 계산한다.

명령값은 STM32에서 PWM으로 환산하고 동일한 S-curve, 전자브레이크, 전류/온도 보호를 적용한다.
ESP32-P4에서는 별도의 장시간 가속 램프를 중복 적용하지 않고 목표 명령을 송신한다.

예: 좌/우 50%, 가속 5초, 배터리 설정 3, 기타 입력 없음:

```text
ID=0x702 DLC=8 DATA=01 F4 32 03 01 F4 00 00
```

## 공통 비상정지

```text
ID=0x703 DLC=1 DATA=FF
```

비상정지는 AS/FM 선택과 무관하게 STM32의 비상정지 래치를 설정한다. 일반 정지에는
비상정지 프레임을 사용하지 말고 좌/우 명령을 모두 0으로 송신한다.

## ESP32-P4 적용 규칙

- 기존 `0x100` 구동 프레임 대신 `0x702`를 사용한다.
- 기존 `0x000` 비상정지 대신 `0x703:FF`를 사용한다.
- 좌우 값은 RPM이 아니라 정규화된 `-1000..1000` 명령으로 송신한다.
- Follow 활성 중에는 새 거리 계산 결과가 없어도 마지막 안전 명령을 50 ms 이하로 갱신한다.
- UWB/ESP-NOW 데이터가 끊기면 즉시 `0x703:FF`를 보내고 구동 송신을 중단한다.
- 재시작은 사용자의 명시적인 비상정지 해제 및 Follow 재시작 동작 후에만 허용한다.
